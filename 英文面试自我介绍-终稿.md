# English project introductions

## Project 1: WeChat Mini Program

I worked on a WeChat Mini Program for member campaigns and coupon services. The platform served over 10,000 members. My main pages were campaign pages, coupon distribution and claim pages, and coupon package purchase pages.

I used TypeScript for the frontend and connected the pages to business APIs. Campaign rules, dates, and coupon states came from the backend, so each page showed the right content and actions. In the claim and purchase flows, I blocked repeated clicks and handled loading, payment results, and failed requests. This avoided duplicate actions and gave users clear feedback.

As the Mini Program grew, its main package became too large. I moved pages that were not needed at startup into subpackages. I also combined repeated home page requests and used frontend cache with Redis. Users downloaded less code at startup, and the app loaded less repeated data.

On the backend, I mainly worked on API design and database access. I used Java 17, Spring Boot 3, MyBatis-Plus, and MySQL. Before issuing a purchased coupon package, the service checked the order and payment result. The refund flow used rollback logic to keep the order, payment, and coupon records consistent if one step failed.

For WeChat login, I checked login data and maintained token state in Redis. I handled token refresh, expiration, and logout. We released updates every week. Because I understood both sides, I could trace production problems from the page to the API and database and fix them faster.

## Project 2: Operations admin system


I worked on the web admin system for the same member platform. Staff used it to manage members, coupons, business settings, and dashboards. Frontend was my main responsibility.

I built the system with React and TypeScript. I used Ant Design for the interface and ECharts for dashboards, arranging fields and charts around each staff task. Complex forms had many rules and status changes. I built shared components for forms, filters, dialogs, and messages, then reused them across modules. TypeScript types checked component inputs and API data. This reduced repeated code, kept pages consistent, and made wrong fields easier to find.

The request layer checked the JWT before each call. If a token was missing or expired, it cleared the local session and returned the user to login. The frontend used RBAC results from the server to control routes and actions. Users saw only the actions available to their role. The server still made the final permission check.

I also worked with backend engineers on member, coupon, and login APIs. We used SpringDoc OpenAPI to confirm fields and error responses before integration. I helped add JUnit 5 tests and used Maven and Docker to reproduce issues. This reduced API mismatches and made bugs easier to repeat and fix.

Together, the Mini Program and admin system included more than 100 pages and features for over 10,000 members. We released updates every week. I worked from requirement review through development, testing, release, and production support.
